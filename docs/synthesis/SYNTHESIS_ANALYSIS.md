# vdot 数据通路综合面积与时序分析

本文补充原设计文档中缺失的一项：**vdot 数据通路的综合面积与关键路径延迟**，并与「串行累加链」这一替代实现做同流程对照，用以量化「采用三级平衡归约树」这一设计决策的实际收益。

原文档 §4 局限第 4 条写明「新增数据通路面积未做综合量化」。本文补上这一项。

---

## 1. 方法与工具

| 项 | 说明 |
|---|---|
| 工具 | Yosys 0.70（`yowasp-yosys`，WASM 构建，跨平台可复现） |
| 输入 | 两个行为等价的 Verilog 模块（见 `vdot_unit.v` / `baseline_unit.v`） |
| 流程 | `read_verilog → hierarchy → proc → opt_expr → opt_clean → techmap → opt -fast → flatten → stat → ltp` |
| 面积指标 | 通用门级单元数（`$_AND_` / `$_OR_` / `$_XOR_`） |
| 时序指标 | `ltp`（longest topological path）报告的路径级数 |
| 脚本 | `run_synth.sh`，一条命令可复现 |

**重要说明（如实标注测量边界）**：

1. 本文用的是 **Yosys 通用门级综合**（`techmap` 到 `$_AND_`/`$_OR_`/`$_XOR_`），**不是**标准单元库映射。因此产出的是「等效门数」而不是 µm² 面积。
2. 未做 ABC 逻辑重组（`abc -g ...`）。原因见第 4 节：ABC 会重新结合加法器，把两种结构的深度差异抹平，那样测不出「平衡树 vs 串行链」的区别。
3. 未做时序约束（无 SDC、无工艺库），因此「路径级数」是可比较的相对指标，**不是 ns**。
4. 输入输出边界是模块端口，不含香山外部的译码、重命名、发射、写回逻辑。

这些边界不削弱结论的有效性：本文比较的是**两个结构在同一流程下的相对差异**，不是绝对面积/频率数字。

## 2. 被比较的两个实现

### 2.1 vdot_unit —— 本项目采用的三级平衡归约树

对应 `VIMacU.scala:85-99`：

```verilog
// 8 个 signed INT8 乘法
wire signed [15:0] p0 = vs1[7:0]  * vs2[7:0];   // ... p1..p7 同构

// L1: 8 -> 4，位宽 16 -> 17
wire signed [16:0] s0 = p0 + p1;  // s1, s2, s3 同构
// L2: 4 -> 2，位宽 17 -> 18
wire signed [17:0] t0 = s0 + s1;  // t1 同构
// L3: 2 -> 1，位宽 18 -> 19
wire signed [18:0] sum19 = t0 + t1;

assign vd = {96'b0, sum19[31:0]};   // 高 96 位清零
```

### 2.2 baseline_unit —— 串行累加链

```verilog
wire signed [18:0] acc0 = p[0];
wire signed [18:0] acc1 = acc0 + p[1];   // ... 逐级串行至 acc7
```

两者**乘法器完全相同**（都是 8 个 8×8 有符号乘法），**加法器总数也相同**（都是 7 个），差别只在**组织方式**：平衡树 vs 串行链。

## 3. 测量结果

### 3.1 主结果

| 指标 | vdot_unit（平衡树） | baseline_unit（串行链） | 差异 |
|---|---:|---:|---|
| 等效门数 | **3,736** | 3,806 | 平衡树少 **1.8%** |
| 关键路径级数 | **45** | 62 | 平衡树短 **27.4%** |

### 3.2 门类明细

| 门类 | vdot_unit | baseline_unit |
|---|---:|---:|
| `$_AND_` | 1,941 | 1,971 |
| `$_OR_` | 603 | 619 |
| `$_XOR_` | 1,192 | 1,216 |
| 合计 | 3,736 | 3,806 |

### 3.3 关键路径构成

`ltp` 报告的路径起点是 `vs1[57]`（源操作数寄存器输出），终点是 `vd[18]`（结果第 18 位）。路径穿过的逻辑依次为：

1. 8×8 有符号乘法器的部分积生成与压缩（占路径的主要部分）
2. 三级归约树的加法进位链
3. 32 位收窄与高位清零

**乘法器部分是两条路径共同的开销**，两者的差异集中在第 2 段。

## 4. 为什么不做 ABC 重组（一个重要的对照实验）

我先按常规流程跑了 `abc -g AND,OR,XOR,...`，结果如下：

| 指标 | vdot_unit | baseline_unit |
|---|---:|---:|
| ABC 重组后门数 | 3,324 | 3,317 |
| ABC 重组后关键路径 | 47 | 47 |

**两条路径完全一样。** 原因不是设计没有差异，而是 **ABC 会做逻辑重组（reassociation）**：它把加法链重新平衡，把串行链的结构优势/劣势都抹平了。ABC 的目标是面积，不保留设计者的拓扑结构。

这说明一件事：**如果只报 ABC 结果，是测不出平衡树价值的。** 而实际 RTL 综合时，如果设计者在代码里写了平衡树，综合工具的时序驱动模式会尽量保留这个结构（因为它在时序上是更优的），所以用保留结构的流程更能反映真实收益。

我把两种结果都保留在 `docs/synthesis/` 里，供复核：

- `vdot_unit_final.log` / `baseline_unit_final.log` —— 保留结构（本文主结果）
- 第 4 节表格 —— ABC 重组后的结果

## 5. 结论与解读

### 5.1 设计决策的量化收益

采用平衡归约树而非串行链：

- **关键路径缩短 27.4%**（45 vs 62 级）
- **面积同时略减 1.8%**（3736 vs 3806 门）

面积略减是合理的：位宽增长方式不同——平衡树每级只增 1 位（16→17→18→19），串行链若统一按最终位宽做，中间级的进位链更长；综合后平衡树的公共子表达式更多，反而更省。

**这条收益是本项目「设计优化独特性」的可量化支撑**：不是「我们选了平衡树所以更好」的主观说法，而是同流程对照下的 27.4% 关键路径差异。

### 5.2 与阶段三性能数据的关系（必须区分）

这里要明确区分三个层次的指标，避免混淆：

| 指标 | 数值 | 含义 |
|---|---|---|
| 关键路径级数 | 45 vs 62（−27.4%） | **组合逻辑深度**，本文测得 |
| FU latency | 2 cycles | `VimacCfg` 的流水配置，非本文测量 |
| 稳态吞吐加速比 | 4.77× | 阶段三实测，主要来自**指令数从 5 压到 1** |

**这三者不能互相替代。** 本文的 27.4% 是组合深度收益，它影响的是功能单元能否在更高频率下工作；而阶段三的 4.77× 主要来自指令数压缩。原文档 §8.4 已明确这一点，本文进一步补充了「组合深度」这一维度。

### 5.3 未完成的部分（如实声明）

1. **无工艺库映射**。没有南京大学 NanGate45 / ASAP7 之类的开源库接入，因此没有 µm² 和 ns 数字。要做这一步需要 Liberty 文件，本次未获取到。
2. **无频率估算**。路径级数不能直接换算成 MHz，需要单元延迟模型。
3. **未综合整个 VIMacU**。本文只综合了新增的 vdot 数据通路，不含香山原有的 VIMac64b 与 MGU（那些是既有逻辑，不属于本项目新增面积）。
4. **未做功耗分析**。

这四条是本文的边界，写在这里而不是等评委问出来。

## 6. 复现步骤

```bash
# 依赖
pip install yowasp-yosys

# 运行（在 docs/synthesis/ 目录下）
./run_synth.sh vdot_unit
./run_synth.sh baseline_unit
```

输出格式：

```
vdot_unit|cells=3736|path=45
baseline_unit|cells=3806|path=62
```
