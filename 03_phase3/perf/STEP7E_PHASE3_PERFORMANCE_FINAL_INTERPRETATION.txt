CIE2026 Phase3.3 VDOT Final Performance Interpretation

1. Measurement status
---------------------
The formal performance benchmark passed.

Measurement mode:
  XiangShan RTL simulation, --no-diff

Functional correctness is not inferred from the performance run alone.
It was independently established earlier by:
  - custom vdot.vv RTL <-> NEMU DiffTest
  - mathematically equivalent RVV baseline RTL <-> NEMU DiffTest

Primary performance counter:
  rdcycle

Samples:
  5

Operations per measured sample:
  256

Warm-up operations per path:
  16

The measured regions are statically unrolled.
There are no loop branches or printf operations inside the measured regions.


2. Compute-only result
----------------------
Custom vdot.vv:
  median cycles / 256 operations = 269
  median cycles per operation    = 1.050781

Standard RVV baseline:
  median cycles / 256 operations = 1283
  median cycles per operation    = 5.011719

Measured steady-state compute speedup:

  baseline_cycles / custom_cycles
  = 4.769517x

Static compute instruction count:
  custom   = 1 instruction / dot product
  baseline = 5 instructions / dot product

Static compute instruction-count ratio:
  5.000000x

5. Correct interpretation of latency and throughput
----------------------------------------------------
The 4.769517x value is a measured steady-state compute-cycle /
throughput speedup from a 256-operation statically unrolled stream.

It must NOT be described as:
  "single-instruction latency speedup = 4.769517x"

Single-operation / functional-unit latency is a separate RTL design
property and should be reported from the RTL design and waveform
evidence.

Therefore the final report should distinguish:

  RTL/FU latency evidence
  versus
  measured steady-state throughput
  versus
  measured end-to-end kernel cycles


6. Counter-boundary interpretation
----------------------------------
The rdcycle measurement uses the same counter-boundary structure for
the custom and baseline kernels.

Fixed measurement-boundary overhead is retained in the raw results.
No unmeasured overhead subtraction is performed.

Because 256 operations are measured per sample, fixed boundary overhead
is amortized across the measured stream.

The reported speedups therefore use the directly observed raw median
cycle counts.


7. rdinstret interpretation
----------------------------
rdinstret is retained as supplementary CSR evidence.

Exact instruction counts for the benchmark are taken from the frozen
Step7C objdump, not inferred from rdinstret values.
